# 웹소켓 명세서 (스크래블) — 백엔드

> 최종 수정: 2026-08-15
> 현재 범위: **만나서(코드·랜덤 매칭) 1:1 채팅 → 방장이 게임 시작 → 각자 칩 7개씩 배분
> → 자기 차례에 판에 단어 놓기(사전 검증 포함)**까지.
> **손패 보충 · 점수 계산 · 게임 끝내기(정상 종료 · 세 번 넘기기 · 나가기)까지
> 됩니다.** 한 판이 처음부터 끝까지 돌아갑니다.

## 🔴 프론트엔드 담당은 이 파일을 보지 마세요

**이 파일은 백엔드 쪽 원본입니다. 복사해 가면 그 순간부터 낡습니다.**
백엔드가 계약을 바꿔도 복사본은 그대로라, 어느 날 조용히 어긋납니다.

**대신 주소를 북마크하세요. 항상 최신입니다.**

| 무엇 | 주소 | 어떻게 최신이 되나 |
|------|------|-------------------|
| **웹소켓** (방·채팅·게임 시작·칩 배분) | **<http://localhost:11000/ws-docs>** | `asyncapi.yaml` 을 요청할 때마다 읽어서 그림 |
| **HTTP API** (플레이어·칩 구성·보드) | **<http://localhost:11000/docs>** | 코드에서 자동 생성 |

`/ws-docs` 에서는 **바로 연결해서 눌러볼 수도 있습니다.** (「직접 해보기」)

> 서버가 켜져 있어야 보입니다. 안 열리면 백엔드 담당에게 서버를 켜달라고 하세요.

이 파일에 있는 내용은 **전부 `/ws-docs` 에도 있습니다.** 여기 있는 건
백엔드가 명세를 고칠 때 참고하는 원본이고, 프론트엔드가 볼 것은 화면입니다.

## 이 문서가 왜 따로 있나

HTTP API는 FastAPI가 스와거(`/docs`)와 `/openapi.json`을 **자동으로** 만들어 줍니다.
하지만 **웹소켓은 자동 문서화가 안 됩니다.** `/docs`에 들어가도 `/ws`는 보이지 않습니다.

그래서 이 문서가 **웹소켓의 계약서**입니다. 이게 없으면 프론트엔드는
"뭘 보내고 뭘 받는지" 알 방법이 아예 없습니다.

그래서 스와거가 해주던 일을 직접 만들었습니다. 네 개가 한 세트입니다.

| | HTTP API | 웹소켓 |
|---|---|---|
| 기계가 읽는 계약 | `/openapi.json` (자동) | **`/asyncapi.yaml`** · `/asyncapi.json` (손으로 씀) |
| 사람이 보는 화면 | `/docs` (자동) | **`/ws-docs`** |
| 사람이 읽는 설명 | `docs/api-contract.md` | **`docs/ws-contract.md`** (이 문서) |

- **원본은 [`docs/asyncapi.yaml`](./asyncapi.yaml) 하나뿐입니다.** `/ws-docs` 화면은
  그 파일을 읽어서 그리기만 하므로, 명세를 고치면 화면이 저절로 따라옵니다.
  (서버를 껐다 켤 필요도 없습니다.)
- "AsyncAPI"는 웹소켓용 명세 표준의 이름입니다. HTTP 쪽 표준이 OpenAPI인 것과 같은 관계입니다.

> ⚠️ **명세는 코드와 자동으로 연결돼 있지 않습니다.** 웹소켓 코드를 고치면
> `asyncapi.yaml`도 **손으로 함께** 고쳐야 합니다. 안 고치면 조용히
> 거짓말하는 문서가 됩니다.

> 📌 **프론트엔드 저장소에 이 파일을 복사해 두지 마세요.**
> 예전에는 양쪽에 같은 파일을 두고 함께 고쳤는데, 그러면 **한쪽만 고치는 날**
> 두 문서가 서로 다른 말을 하게 됩니다. 어느 쪽이 맞는지는 아무도 모릅니다.
>
> 이제 **원본은 `docs/asyncapi.yaml` 하나**이고, 프론트엔드는 그것을 그린
> `/ws-docs` 를 봅니다. 고칠 곳도 볼 곳도 하나씩이라 어긋날 수가 없습니다.

## 웹소켓은 HTTP와 뭐가 다른가

| | HTTP API | 웹소켓 |
|---|---|---|
| 방식 | 물어보면 답하고 **끊음** | 한 번 연결하면 **계속 이어져 있음** |
| 누가 먼저 말하나 | 프론트엔드만 | **양쪽 다** |
| 언제 쓰나 | 목록 조회, 저장 등 | "누가 방에 들어왔다"처럼 **남 때문에 생긴 일**을 알릴 때 |

프론트엔드가 물어보지 않아도 백엔드가 먼저 말을 걸 수 있다 — 이게 핵심 차이입니다.

## 만나는 방법이 두 가지입니다

| 주소 | 누가 쓰나 | 무엇을 하나 |
|------|-----------|-------------|
| **`ws://localhost:11000/ws/rooms`** | 방장 | 방을 만들고 **아는 사람**을 기다림 |
| **`ws://localhost:11000/ws/rooms/{code}`** | 친구 | 코드로 그 방에 들어감 |
| **`ws://localhost:11000/ws/match`** | 아무나 | **모르는 사람**과 짝지어짐 (선착순) |
| `ws://localhost:11000/ws` | — | 연결 확인용 (메아리). 실제 기능 아님 |

> 📌 **어떻게 만났든 그 뒤는 완전히 같습니다.** 같은 방, 같은 채팅 규칙을 씁니다.
> 만나는 방법만 다를 뿐입니다.

`http://`가 아니라 **`ws://`** 입니다. 포트는 HTTP API와 **같은 11000**을 씁니다.
(같은 서버가 두 가지를 함께 처리합니다.)

## 전체 흐름 한눈에

```
방장                                    친구
 │                                       │
 ├─ /ws/rooms?nickname=수진 접속          │
 │                                       │
 │  ◀── room_created (code: K7Q2)      │
 │      화면에 코드 띄우고 기다림          │
 │                                       │
 │   ······ 코드를 친구에게 알려줌 ······▶ │
 │                                       │
 │                    /ws/rooms/K7Q2?nickname=엘리 접속 ─┤
 │                                       │
 │  ◀── guest_joined (엘리)   joined ──▶ │
 │      ⬑ 요청하지 않았는데 온 소식        │
 │                                       │
 │        두 명 다 모임 (status: playing) │
 │        아직 대기 화면입니다             │
 │                                       │
 ├─ {"type":"message","text":"안녕"} ──▶ │
 │                        ◀── message (from: 수진, at: ...)
 │                                       │
 │ ◀── message (from: 엘리) ─────────────┤
 │                                       │
 ├─ {"type":"start"} ──▶ (방장만)         │
 │                                       │
 │ ◀── game_started ────────────────────▶│
 │      ⬑ 양쪽에 똑같이 갑니다             │
 │                                       │
 │   ★ 여기서 양쪽 다 게임 화면으로 전환 ★  │
```

**`guest_joined` 가 이 구조의 핵심입니다.** 방장은 아무것도 요청하지 않았는데
소식을 받습니다. HTTP였다면 방장이 "혹시 들어왔나요?"를 계속 물어봐야 했습니다.

**두 명이 모였다고 게임 화면으로 넘어가지 않습니다.** 모인 것과 시작한 것은
다릅니다. 화면이 바뀌는 시점은 오직 `game_started` 를 받았을 때입니다.
(→ [게임 시작 (방장만)](#게임-시작-방장만))

# `/ws/rooms` — 방 만들고 기다리기

## 이 통로가 왜 웹소켓인가

채팅은 **1:1**입니다. 흐름이 이렇습니다.

1. 방장이 닉네임을 들고 접속한다
2. 서버가 **방을 만들고 초대 코드를 바로 보낸다**
3. 방장은 연결을 붙잡은 채 **기다린다**
4. *(다음 기능)* 친구가 코드를 치고 들어오면 → 방장에게 알려준다

코드만 받는 것이라면 HTTP API로도 됩니다. 하지만 방장은 그 뒤에 **"친구가
들어왔다"는 소식을 받아야** 합니다. 그건 방장이 요청한 게 아니라 남 때문에
생긴 일이라, 서버가 먼저 말을 걸 수 있어야 합니다. 그러려면 방장의 연결이
그때까지 **살아 있어야** 하고, 그래서 방을 만드는 순간부터 웹소켓입니다.

> HTTP로 방을 만들면 기다리는 연결이 없어서 **아무도 들어올 수 없는 죽은 방**이 됩니다.

## ① 접속 주소

```
ws://localhost:11000/ws/rooms?nickname=수진
```

## ② 접속할 때 넘기는 값

주소 뒤에 물음표를 붙여 보냅니다. (쿼리 파라미터)

| 이름 | 타입 | 필수 | 규칙 |
|------|------|------|------|
| `nickname` | string | ✅ | **플레이어 추가와 완전히 동일** (공백 제거 후 1~20자) |

> 방 이름·정원은 받지 않습니다. 이름은 `"OO님의 방"`으로 자동으로 지어지고,
> 정원은 4로 고정입니다. (채팅은 1:1이라 실제로는 2명만 씁니다)

## ③ 접속 직후 서버가 먼저 보내는 것

연결되자마자 **방이 만들어지고** 이 메시지가 옵니다.

```json
{
  "type": "room_created",
  "code": "K7Q2",
  "name": "수진님의 방",
  "host_nickname": "수진",
  "max_players": 4
}
```

| 필드 | 설명 |
|------|------|
| `code` | **초대 코드.** 이걸 화면에 띄워 친구에게 알려주세요 |
| `name` | 자동으로 지어진 방 이름 |
| `host_nickname` | 공백이 정리된 최종 닉네임 |
| `max_players` | 정원. 지금은 항상 `4` |

**초대 코드 형식** — 대문자·숫자 4자리. **`O` `I` `L` `0` `1`은 나오지 않습니다.**
코드를 불러줄 때 "영어 오야, 숫자 영이야?"를 묻지 않아도 되게 하려고 뺐습니다.

> ⚠️ **이걸 받은 뒤 연결을 끊지 마세요.** 연결이 살아 있는 동안만 그 코드가
> 유효합니다. 끊으면 방도 함께 없어집니다. (아래 ⑥ 참고)

## ④ 프론트엔드 → 백엔드 (보내는 메시지)

**보낼 것이 없습니다.** 접속만 하고 가만히 있으면 됩니다.

말을 걸면 "아직 상대가 안 들어왔다"는 `error`가 돌아옵니다. (연결은 안 끊깁니다)
채팅 메시지 형식은 채팅 기능을 만들 때 정합니다.

## ⑤ 백엔드 → 프론트엔드 (받는 메시지)

**항상 JSON**이며, **`type` 필드로 종류를 구분**합니다.

| `type` | 언제 오나 | 그 다음 |
|--------|-----------|---------|
| `room_created` | 접속 직후 1회 | 코드를 화면에 띄우고 기다림 |
| **`guest_joined`** | **친구가 들어왔을 때** | 대화 화면으로 넘어가면 됨 |
| **`guest_left`** | **친구가 나갔을 때** | 다시 기다리는 화면으로. **같은 코드가 계속 유효** |
| `error` | 닉네임이 잘못됨 | **연결이 끊깁니다** (코드 `1008`) |
| `error` | 말을 걺 (채팅 없음) | 연결은 유지됩니다 |

```json
{ "type": "guest_joined", "nickname": "엘리" }
{ "type": "guest_left",   "nickname": "엘리" }
```

```javascript
const ws = new WebSocket("ws://localhost:11000/ws/rooms?nickname=수진");

ws.onmessage = (e) => {
  const data = JSON.parse(e.data);       // 문자열로 오므로 JSON.parse 필요
  if (data.type === "room_created") 화면에코드띄우기(data.code);
  if (data.type === "guest_joined")  대화화면으로(data.nickname);
  if (data.type === "guest_left")    다시기다리기(data.nickname);
  if (data.type === "error")         알림(data.message);
};
```

> 📌 **`error`가 두 가지 상황에서 옵니다.** 하나는 끊기고 하나는 안 끊깁니다.
> 구분하려면 `ws.onclose`가 불리는지를 보면 됩니다.

## ⑥ 연결이 끊기는 경우

| 상황 | 무슨 일이 생기나 |
|------|------------------|
| 방장이 탭·창을 닫음 | 방은 `finished`. 들어와 있던 친구도 **함께 끊깁니다** |
| 들어와 있던 친구가 나감 | `guest_left`가 옴. 방은 다시 `waiting` — **같은 코드로 다른 사람이 들어올 수 있습니다** |
| 서버를 껐다 켬 (`--reload` 포함) | 모든 연결이 끊기고, 살아 있던 방은 **전부 무효** |
| 닉네임이 규칙에 안 맞음 | `error`를 받은 뒤 `1008`로 끊김. **방은 만들어지지 않습니다** |

> ⚠️ **방장이 끊기면 그 코드는 죽습니다.** 다시 연결하면 **새 방·새 코드**가
> 만들어집니다. 친구에게 새 코드를 다시 알려줘야 합니다.
>
> 개발 중에는 백엔드가 코드를 고칠 때마다 서버가 다시 시작되므로
> **연결이 자주 끊깁니다.** 정상입니다.

# `/ws/rooms/{code}` — 코드로 방에 들어가기

친구에게 받은 코드로 그 방에 들어갑니다.

## ① 접속 주소

```
ws://localhost:11000/ws/rooms/K7Q2?nickname=엘리
```

**소문자로 쳐도 됩니다.** 서버가 대문자로 맞춰줍니다.
(코드는 눈으로 보고 옮겨 적는 값이라, 대소문자로 막으면 불친절합니다)

## ② 넘기는 값

| 자리 | 타입 | 필수 | 규칙 |
|------|------|------|------|
| `{code}` (주소 안) | string | ✅ | 방장에게 받은 초대 코드 |
| `nickname` (물음표 뒤) | string | ✅ | **방 만들 때와 완전히 동일** (공백 제거 후 1~20자) |

## ③ 접속 직후 서버가 먼저 보내는 것

성공하면 바로 이게 옵니다.

```json
{
  "type": "joined",
  "code": "K7Q2",
  "host_nickname": "수진",
  "guest_nickname": "엘리"
}
```

`host_nickname`은 화면에 "수진님과의 대화"처럼 띄우는 데 쓰세요.

## ④ 프론트엔드 → 백엔드 (보내는 메시지)

**보낼 것이 없습니다.** 채팅 메시지 형식은 채팅 기능을 만들 때 정합니다.

## ⑤ 백엔드 → 프론트엔드 (받는 메시지)

| `type` | 언제 오나 | 그 다음 |
|--------|-----------|---------|
| `joined` | 들어가기 성공 | 대화 화면으로 |
| **`host_left`** | **방장이 나감** | **직후 연결도 닫힘** (`1001`). 그 코드는 죽음 |
| `error` | 못 들어감 | **연결이 끊깁니다** (`1008`) |

**`error`의 `message`로 오는 것들**

| 메시지 | 뜻 |
|--------|-----|
| `그런 방이 없습니다. 코드를 다시 확인해 주세요` | 없는 코드이거나, 방장이 이미 나간 코드 |
| `방이 꽉 찼습니다` | 이미 두 명이 모여 있음 |
| 닉네임 규칙 위반 메시지 | 방 만들 때와 같음 |

> 📌 **"없는 코드"와 "방장이 나간 코드"를 구분해서 알려주지 않습니다.**
> 어느 쪽이든 친구가 할 수 있는 일은 똑같고(코드를 다시 받기), 구분해 주면
> 아무 코드나 넣어보며 "이 코드는 있었네"를 알아내는 데 쓰일 수 있습니다.

## ⑥ 연결이 끊기는 경우

| 상황 | 무슨 일이 생기나 |
|------|------------------|
| 내가 탭을 닫음 | 방장에게 `guest_left`가 감. 자리가 비어 다른 사람이 들어올 수 있음 |
| 방장이 나감 | `host_left`를 받고 **함께 끊김** (`1001`) |
| 코드·닉네임이 틀림 | `error`를 받고 끊김 (`1008`) |

## 확인 방법

브라우저 개발자도구 콘솔에서 창 두 개로 해볼 수 있습니다.
(`/ws-docs` 화면의 "직접 해보기"에서도 됩니다)

```javascript
// 창 1 — 방장
const host = new WebSocket("ws://localhost:11000/ws/rooms?nickname=수진");
host.onmessage = (e) => console.log("방장:", e.data);

// 창 2 — 친구 (위에서 받은 코드를 넣으세요)
const guest = new WebSocket("ws://localhost:11000/ws/rooms/여기에코드?nickname=엘리");
guest.onmessage = (e) => console.log("친구:", e.data);
```

기대 결과:

```
방장: {"type":"room_created","code":"K7Q2", ...}
친구: {"type":"joined","code":"K7Q2","host_nickname":"수진","guest_nickname":"엘리"}
방장: {"type":"guest_joined","nickname":"엘리"}     ← 요청하지 않았는데 온 소식
```

# `/ws` — 연결 확인용 (메아리)

맨 처음 "웹소켓이 되는지" 확인하려고 만든 통로입니다. **실제 기능이 아닙니다.**

- 접속할 때 넘기는 값 없음
- 접속 직후: `{"type":"connected","message":"웹소켓 연결됨"}`
- 아무 문자열이나 보내면 `{"type":"echo","message":"<보낸 그대로>"}`

> 실제 기능이 다 붙으면 이 통로는 없앨 예정입니다.

# `/ws/match` — 랜덤 매칭 (모르는 사람과)

코드를 주고받지 않고, **아무나 기다리는 사람과 짝지어 줍니다.**

## 흐름

```
가 (먼저 옴)                            나 (나중에 옴)
 ├─ /ws/match?nickname=가 접속            │
 │  ◀── waiting (position: 1)             │
 │      "상대를 찾는 중…" 표시             │
 │                                        │
 │                  /ws/match?nickname=나 접속 ─┤
 │                                        │
 │  ◀── matched (상대: 나)   matched (상대: 가) ──▶
 │      ⬑ 요청하지 않았는데 온 소식        │
 │                                        │
 │         이후 채팅은 코드로 만났을 때와 동일
```

## 짝짓는 순서 — 선착순

**먼저 와서 기다린 사람이 먼저 짝을 만납니다.** 은행 번호표와 같습니다.

> 왜 "랜덤"인데 순서를 지키나: 누구와 만날지는 알 수 없지만, 기다린
> 순서까지 뒤죽박죽이면 **먼저 온 사람이 계속 밀려서** 영영 짝을 못 만나는
> 일이 생깁니다. 그건 랜덤이 아니라 불공평한 것입니다.

## ① 접속 주소

```
ws://localhost:11000/ws/match?nickname=엘리
```

## ② 넘기는 값

| 이름 | 타입 | 필수 | 규칙 |
|------|------|------|------|
| `nickname` | string | ✅ | **다른 곳과 완전히 동일** (공백 제거 후 1~20자) |

## ③ 접속 직후 서버가 먼저 보내는 것

**둘 중 하나**가 옵니다.

기다리는 사람이 **없으면** — 줄을 섭니다.

```json
{ "type": "waiting", "position": 1, "nickname": "엘리" }
```

기다리는 사람이 **있으면** — 바로 짝이 됩니다.

```json
{ "type": "matched", "code": "7AH3", "partner_nickname": "수진" }
```

| 필드 | 설명 |
|------|------|
| `position` | 줄에서 내 순번. `1`이면 다음 사람과 바로 짝이 됨 |
| `partner_nickname` | 상대 닉네임. "OO님과의 대화"처럼 띄우세요 |
| `code` | 만들어진 방 코드. **랜덤 매칭에서는 쓸 일이 없습니다** (누구에게 알려줄 코드가 아님) |

> ⚠️ **`waiting`을 받으면 연결을 그대로 두세요.** 끊으면 줄에서 빠집니다.
> 다음 사람이 오면 **요청하지 않아도** `matched`가 옵니다.

## ④~⑤ 채팅

짝이 지어진 뒤는 **아래 "채팅 메시지" 절과 완전히 같습니다.**
먼저 기다린 사람이 방장이 되지만, **채팅에서 하는 일은 똑같으므로
화면에서 구분해 보여줄 필요가 없습니다.**

## ⑥ 상대가 나갔을 때 — **연결은 끊기지 않습니다**

```json
{ "type": "partner_left", "nickname": "수진" }
```

남은 사람은 잘못이 없으므로 **서버가 알아서 다시 줄을 세워 줍니다.**
처음부터 다시 접속하게 하면 기다렸던 시간이 없던 일이 되고 줄 맨 뒤로
밀리기 때문입니다.

**`partner_left` 바로 뒤에 둘 중 하나가 옵니다.**

| 그 다음에 오는 것 | 뜻 |
|---|---|
| `waiting` | 기다리는 사람이 없어서 **줄 맨 앞**에 다시 섰음 |
| `matched` | 마침 기다리는 사람이 있어서 **바로 새 짝**이 생겼음 |

```
상대가 나감 → partner_left → waiting   (기다리는 사람 없음)
                          └→ matched   (기다리는 사람 있음 → 바로 연결)
```

> ⚠️ **새 짝이 생기면 방도 새로 만들어집니다.** `code`가 달라지고,
> **이전 대화는 이어지지 않습니다.** 화면에서는 대화창을 비우고
> "상대가 나갔습니다. 새 상대를 찾는 중…" 정도를 띄우면 됩니다.

**그 밖의 경우**

| 상황 | 무슨 일이 생기나 |
|------|------------------|
| 줄 서서 기다리는 중에 나감 | 조용히 줄에서 빠짐. 아무에게도 영향 없음 |
| 내가 나감 | 상대가 `partner_left`를 받고 다시 줄을 섬 |

## 새치기하지 않습니다

내가 다시 줄을 설 때, **계속 기다리고 있던 사람보다 앞서지 않습니다.**

기다리던 사람이 있으면 줄에 서지 않고 **그 사람과 바로 짝**이 됩니다.
이때 방장은 **더 오래 기다린 쪽**이 됩니다.

## 확인 방법

창 두 개를 띄우면 짝이 지어집니다.

```javascript
// 창 1
const a = new WebSocket("ws://localhost:11000/ws/match?nickname=가");
a.onmessage = (e) => console.log("가:", e.data);

// 창 2 — 이걸 열면 창 1에 matched 가 뜹니다
const b = new WebSocket("ws://localhost:11000/ws/match?nickname=나");
b.onmessage = (e) => console.log("나:", e.data);

// 짝이 지어진 뒤
a.send(JSON.stringify({ type: "message", text: "안녕하세요" }));
```

# 채팅 메시지 (양쪽 공통)

**어떻게 만났든(코드 · 랜덤 매칭), 누구든(방장 · 친구) 규칙이 완전히
같습니다.** 1:1이라 양쪽이 하는 일이 똑같기 때문입니다.

## 보내기

**문자열이 아니라 JSON으로** 보냅니다.

```javascript
ws.send(JSON.stringify({ type: "message", text: "안녕" }));
```

| 필드 | 타입 | 필수 | 규칙 |
|------|------|------|------|
| `type` | string | ✅ | `"message"` 고정 |
| `text` | string | ✅ | 할 말. 앞뒤 공백 제거 후 **1~500자** |

## 받기

```json
{
  "type": "message",
  "from": "수진",
  "text": "안녕 엘리",
  "at": "2026-08-08T13:22:38.694059"
}
```

| 필드 | 설명 |
|------|------|
| `from` | 보낸 사람의 닉네임 |
| `text` | 보낸 내용 (앞뒤 공백이 정리된 값) |
| `at` | **DB가 저장하면서 찍은** 시각 (ISO 8601) |

> 📌 **`at`은 서버 시계입니다.** 각자 컴퓨터의 시계를 쓰면 시계가 조금씩
> 달라서 두 사람 화면의 대화 순서가 어긋납니다.
> 저장된 기록의 시각과도 **한 글자도 다르지 않습니다.**

## 저장

주고받은 말은 **DB의 `messages` 테이블에 저장됩니다.**

**저장이 먼저, 전달이 나중입니다.** 전달을 먼저 하면 저장이 실패했을 때
"화면에는 떴는데 기록에는 없는 말"이 생깁니다. 나중에 대화를 꺼내 보면
조용히 한 줄이 비어 있게 되는데, 그게 훨씬 나쁩니다.

- **거절된 메시지는 저장되지 않습니다.** (형식 오류·빈 내용·500자 초과·상대 없음)
- 연결이 다 끊긴 뒤에도 기록은 남습니다.
- 방이 지워지면 그 방의 대화도 함께 지워집니다.

### 지난 대화 불러오기

**방에 들어간 직후 `history` 가 옵니다.** (`joined` 바로 뒤)

```json
{
  "type": "history",
  "messages": [
    { "from": "엘리", "text": "안녕하세요",  "at": "2026-08-15T16:32:11.100000" },
    { "from": "수진", "text": "반가워요",    "at": "2026-08-15T16:32:19.400000" },
    { "from": "엘리", "text": "게임 할까요", "at": "2026-08-15T16:32:25.900000" }
  ]
}
```

- **오래된 것부터** 시간 순서로 옵니다. 위에서 아래로 그대로 그리면 됩니다
- 대화가 없으면 **빈 목록** `[]` 이 옵니다 (안 보내지 않습니다 — 프론트가
  "아직 안 온 건가, 없는 건가"를 기다리게 되니까요)
- 최대 **100줄**
- **들어온 사람에게만** 갑니다. 방장은 처음부터 보고 있었으니 안 갑니다

> ⚠️ **방이 살아 있는 동안의 대화입니다.** 방장이 나가면 그 방은 끝나고,
> 다시 만든 방은 **다른 방**이라 대화도 처음부터입니다.
> (친구가 나갔다 같은 코드로 다시 들어오는 경우에 지난 대화가 보입니다)

> ⚠️ **내가 보낸 말은 나에게 되돌아오지 않습니다.**
> 내 말은 내 화면에 바로 그리세요. 되돌려 주면 같은 말이 두 번 그려지기 쉽습니다.

## 잘못 보냈을 때

`error`가 돌아오지만 **연결은 끊기지 않습니다.** 고쳐서 다시 보내면 됩니다.

| 상황 | `message` |
|------|-----------|
| 혼자 있을 때 보냄 | `상대가 아직 들어오지 않았습니다` |
| 그냥 문자열을 보냄 | `JSON 으로 보내주세요. 예: ...` |
| 모르는 `type` | `{"type":"message","text":"..."} 또는 {"type":"start"} 형식으로 보내주세요` |
| 빈 내용 / 공백만 | `빈 메시지는 보낼 수 없습니다` |
| 500자 초과 | `메시지는 500자 이하여야 합니다` |

## 확인 방법

창 두 개를 띄워 서로 말을 걸어보세요.

```javascript
// 창 1 — 방장
const host = new WebSocket("ws://localhost:11000/ws/rooms?nickname=수진");
host.onmessage = (e) => console.log("방장:", e.data);
// 친구가 들어온 뒤에
host.send(JSON.stringify({ type: "message", text: "안녕 엘리" }));

// 창 2 — 친구 (위에서 받은 코드를 넣으세요)
const guest = new WebSocket("ws://localhost:11000/ws/rooms/여기에코드?nickname=엘리");
guest.onmessage = (e) => console.log("친구:", e.data);
guest.send(JSON.stringify({ type: "message", text: "안녕하세요" }));
```

# 게임 시작 (방장만)

**두 사람이 다 모여도 게임은 저절로 시작되지 않습니다.** 들어오자마자
판이 시작되면 준비할 틈이 없기 때문입니다. **방장이 시작을 눌러야** 합니다.

채팅과 **같은 연결**을 씁니다. 새로 접속할 필요가 없습니다.

## 방장이 누구인가

| 만난 방법 | 방장 |
|-----------|------|
| 코드로 만남 | 방을 만든 사람 (`/ws/rooms`로 접속한 쪽) |
| 랜덤 매칭 | **먼저 와서 기다린 사람** |

> 📌 랜덤 매칭에서는 코드를 만든 사람이 없지만 방장은 정해져 있습니다.
> 누가 방장인지는 접속 직후 받는 메시지로 알 수 있습니다 —
> `room_created`를 받았으면 나는 방장, `joined`를 받았으면 아닙니다.
> `matched`를 받은 경우에는 **서버가 알려주지 않습니다.**
> (아래 "아직 없는 것" 참고)

## 보내기

```javascript
ws.send(JSON.stringify({ type: "start" }));
```

| 필드 | 타입 | 필수 | 규칙 |
|------|------|------|------|
| `type` | string | ✅ | `"start"` 고정 |

보낼 게 이것뿐입니다. 누가 눌렀는지는 **연결로 판단**하므로 닉네임을
같이 보낼 필요가 없습니다. (보내도 무시합니다)

## 받기 — 양쪽 모두에게, 단 **내용이 조금 다릅니다**

```json
{
  "type": "game_started",
  "code": "K7Q2",
  "host_nickname": "수진",
  "guest_nickname": "엘리",
  "first_turn": "엘리",
  "at": "2026-08-15T14:02:11.482913",

  "rack": ["E", "A", "T", "?", "R", "N", "S"],
  "partner_tile_count": 7,
  "tiles_left": 86
}
```

| 필드 | 양쪽 같음? | 설명 |
|------|-----------|------|
| `code` | 같음 | 방 코드 |
| `host_nickname` | 같음 | 방장 닉네임 |
| `guest_nickname` | 같음 | 친구 닉네임 |
| `first_turn` | 같음 | **먼저 두는 사람의 닉네임** |
| `at` | 같음 | DB가 저장하면서 찍은 시작 시각 (ISO 8601) |
| `tiles_left` | 같음 | 가방에 남은 칩 개수 (시작 직후 **86**) |
| **`rack`** | **다름** | **받는 사람 본인의 칩 7개** |
| `partner_tile_count` | 같음* | 상대가 든 칩 **개수만** (시작 직후 7) |

> \* 시작 직후에는 둘 다 7이라 같아 보이지만, 뜻은 "**상대**가 든 개수"라
> 앞으로 서로 달라질 수 있는 값입니다.

### ⚠️ `rack`은 사람마다 다릅니다

**내 칩은 나에게만 갑니다.** 상대의 `rack`은 **아예 보내지 않습니다.**
개수(`partner_tile_count`)만 갑니다.

프론트엔드가 "안 그리면 되지"로 처리하면 안 됩니다 — 브라우저 개발자
도구를 열면 오간 내용이 그대로 보입니다. **보내지 않는 것만이 가리는
방법**이라 서버에서 갈라 보냅니다.

상대 칩은 **뒷면 `partner_tile_count`장**으로 그리세요.

> 📌 **누른 사람에게도 옵니다.** 채팅과 다른 점입니다.
> 채팅은 내 말이 나에게 돌아오지 않지만, 게임 시작은 서버가 정해 주는
> 값(누가 선공인지·내 칩이 무엇인지)이 있어서 방장도 받아서 그립니다.
> 누른 즉시 화면을 바꾸지 말고, `game_started`를 받고 바꾸세요.
> (자세히는 바로 아래 "게임 페이지로 전환")

> 📌 **`first_turn`은 무작위입니다.** 방장이 아닙니다.
> 스크래블에서 선공은 유리한 자리라, 방을 만들었다는 이유만으로 매번
> 먼저 두면 공평하지 않기 때문입니다.

## 칩 배분

시작하면 **칩 100개를 섞어 각자 7개씩** 나눠 줍니다. `100 - 7 - 7 = 86`개가
가방에 남습니다.

- 칩이 무엇무엇 있는지(글자·개수·점수)는 [`GET /api/game/setup`](./api-contract.md)
  에 있습니다. **시작할 때 한 번만** 받아 두면 됩니다.
- `rack`의 각 글자는 그 API의 `tiles`에 있는 `letter`와 같습니다.
- `"?"`는 **빈 타일**입니다. 아무 글자로나 쓸 수 있는 대신 0점입니다.
  `rack`에 `"?"`가 들어올 수 있으니 화면에서 처리해 주세요.

> 📌 **매번 다르게 섞입니다.** 예측할 수 없는 방식으로 섞기 때문에,
> 상대가 다음에 뽑을 칩을 미리 알아낼 수 없습니다.

> ⚠️ **칩을 더 뽑거나 바꾸는 기능은 아직 없습니다.** 지금은 시작할 때
> 한 번 나눠 주는 것까지입니다. 단어를 놓고 그만큼 다시 채우는 것은
> 다음 기능입니다.

> ⚠️ **칩은 서버 메모리에만 있습니다.** DB에 저장하지 않습니다.
> 연결이 끊기면 그 판의 칩은 사라집니다.

## 게임 페이지로 전환 — **`game_started`를 받았을 때**

> 백엔드는 화면을 그리지 않습니다. **"지금 전환하라"는 신호만** 보냅니다.
> 화면을 어떻게 만들지는 프론트엔드가 정합니다. 이 절은 **언제** 바꿔야
> 하는지, 그 시점만 약속합니다.

### 어떤 신호에 어떤 화면인가

| 받은 메시지 | 있어야 할 화면 |
|-------------|----------------|
| `room_created` | 대기 화면 (코드를 띄우고 친구를 기다림) |
| `joined` | 대기 화면 (들어왔음) |
| `waiting` | 대기 화면 (줄 서는 중) |
| `matched` | 대기 화면 (짝은 만났지만 **아직 시작 전**) |
| `guest_joined` | 대기 화면 (여기서 방장에게 **시작 버튼**을 보여주면 됩니다) |
| **`game_started`** | **게임 화면** ← 여기서 전환 |
| `guest_left` / `partner_left` / `host_left` | 대기 화면으로 되돌아감 |

### 방장 쪽 — 누른 즉시 바꾸지 마세요

시작 버튼을 누른 그 순간에 화면을 바꾸면 **안 됩니다.** 요청이 거절될 수
있기 때문입니다(아직 상대가 없음 · 이미 시작함 · 저장 실패). 그러면 화면은
게임인데 실제로는 시작되지 않은 상태가 됩니다.

```
버튼 누름 → {"type":"start"} 전송 → 버튼을 잠시 비활성화하고 기다림
                                    ├─ game_started 오면 → 게임 화면으로 전환
                                    └─ error 오면      → 대기 화면 그대로, 사유 표시
```

### 친구 쪽 — 아무것도 안 눌렀는데 화면이 바뀝니다

친구는 시작 버튼이 없습니다. **가만히 있는데 서버가 먼저 말을 걸어와서**
화면이 바뀝니다. 이게 이 기능을 웹소켓으로 만든 이유 그 자체입니다.
HTTP였다면 친구가 "혹시 시작했나요?"를 계속 물어봐야 했을 것입니다.

> 📌 그래서 친구 쪽 화면은 **`game_started`를 받을 준비가 항상 되어
> 있어야** 합니다. 대기 화면에서 연결을 끊거나 리스너를 떼면 시작해도
> 넘어가지 못합니다.

### 서버가 준 값으로 그립니다

게임 화면에 필요한 값(누가 먼저 두는지, 내 칩이 무엇인지)을 각자 계산하지
말고 **받은 값을 그대로** 쓰세요. 각자 계산하면 한쪽만 틀린 화면을 그리게
되고, 그건 찾아내기 어렵습니다.

**`rack`만 사람마다 다르고, 나머지는 양쪽이 같습니다.** 내 칩은 나에게만
오고 상대 칩은 개수만 옵니다.

### 게임 화면에서 되돌아오는 경우

| 상황 | 받는 메시지 | 연결 | 되돌아갈 곳 |
|------|-------------|------|-------------|
| 친구가 나감 (코드로 만난 방) | `guest_left` | **유지됨** | 대기 화면. 새 친구가 들어오면 다시 시작 가능 |
| 방장이 나감 (코드로 만난 방) | `host_left` | **끊김** (1001) | 처음 화면. 새로 접속해야 함 |
| 상대가 나감 (랜덤 매칭) | `partner_left` | **유지됨** | 대기 화면. 서버가 알아서 다시 줄 세워 줍니다 |

> ⚠️ **`game_over` 같은 메시지는 없습니다.** 위 세 가지를 받으면 게임이
> 끝난 것으로 처리하세요.

### ⚠️ 새로고침하면 게임이 사라집니다

게임 화면에서 브라우저를 새로고침하면 **웹소켓 연결이 끊깁니다.** 연결이
끊기면 서버 입장에서는 나간 것이고, 방도 함께 정리됩니다. 다시 접속해도
같은 게임으로 돌아올 수 없습니다.

방이 서버 메모리에만 있어서 그렇습니다. **되돌아오는 기능(재접속)은 아직
없습니다.** 게임 화면에서 새로고침을 막거나, 최소한 "나가시겠습니까?"를
띄우는 편이 안전합니다.

## 잘못 보냈을 때

요청한 사람에게만 `error`가 돌아옵니다. **상대에게는 아무것도 가지
않습니다.** 연결도 끊기지 않습니다.

| 상황 | `message` |
|------|-----------|
| 방장이 아닌 사람이 보냄 | `방장만 게임을 시작할 수 있습니다` |
| 이미 시작한 게임 (두 번 누름) | `이미 시작된 게임입니다` |
| 혼자 있을 때 보냄 | `아직 상대가 들어오지 않았습니다` |
| 저장에 실패 | `게임을 시작하지 못했습니다. 잠시 후 다시 눌러 주세요` |

## 게임 중에 상대가 나가면

그 판은 **거기서 끝납니다.** 상대 없는 스크래블은 이어갈 수 없기 때문입니다.

- 코드로 만난 방 → 방장은 `guest_left`를 받습니다. 방은 다시 대기 상태가
  되고, **새 친구가 들어오면 다시 시작할 수 있습니다.**
- 랜덤 매칭 → 기존대로 `partner_left`를 받고 다시 줄을 섭니다. 새 짝을
  만나면 그때 다시 `start`를 보내야 합니다.

> ⚠️ 이때 **`game_over` 같은 메시지는 따로 가지 않습니다.** 프론트엔드는
> `guest_left` / `partner_left`를 받으면 게임이 끝난 것으로 처리하세요.

## 저장

시작한 시각이 DB `rooms.started_at`에 남습니다. 아직 시작 안 한 방은 비어
있습니다(NULL).

> ⚠️ `rooms.status`로는 시작 여부를 알 수 없습니다. `status`가 `playing`이
> 되는 시점은 **두 사람이 다 모였을 때**지 시작을 누른 때가 아닙니다.
> 그래서 칸을 따로 만들었습니다.

## 확인 방법

```javascript
// 창 1 — 방장
const host = new WebSocket("ws://localhost:11000/ws/rooms?nickname=수진");
host.onmessage = (e) => console.log("방장:", e.data);

// 아직 혼자일 때 눌러보기 → "아직 상대가 들어오지 않았습니다"
host.send(JSON.stringify({ type: "start" }));

// 창 2 — 친구 (위에서 받은 코드를 넣으세요)
const guest = new WebSocket("ws://localhost:11000/ws/rooms/여기에코드?nickname=엘리");
guest.onmessage = (e) => console.log("친구:", e.data);

// 친구가 눌러보기 → "방장만 게임을 시작할 수 있습니다"
guest.send(JSON.stringify({ type: "start" }));

// 방장이 누르기 → 양쪽 창에 game_started
host.send(JSON.stringify({ type: "start" }));

// 한 번 더 누르기 → "이미 시작된 게임입니다"
host.send(JSON.stringify({ type: "start" }));
```

# 차례 지키기

**자기 차례에만 놓을 수 있습니다.** 판은 하나뿐이라, 차례가 없으면 둘이
동시에 놓을 수 있고 그러면 먼저 도착한 쪽이 이기는 경주가 됩니다.
순서가 있는 게임에서 그건 규칙이 없는 것과 같습니다.

## 어떻게 정해지고 어떻게 넘어가나

| | |
|---|---|
| 선공 | **무작위.** 방장이 아닙니다 |
| 넘어가는 때 | **놓기에 성공했을 때만** |
| 거절됐을 때 | 차례는 **그대로 나에게** 있습니다 |

거절(사전에 없는 단어·잘못된 자리)로 차례가 넘어가면, 실수 한 번에 한
턴을 잃게 됩니다. 그건 벌칙이지 규칙이 아닙니다.

## 내 차례인지 어떻게 아나 — **`your_turn`**

`game_started` 와 `board_updated` **둘 다**에 들어 있습니다.

```json
{ "turn": "엘리", "your_turn": false }
```

| 필드 | 쓰임 |
|------|------|
| `turn` | **화면에 보여줄 때만.** "엘리님 차례입니다" |
| **`your_turn`** | **판단은 이걸로.** 참이면 내 차례 |

> 🔴 **`turn === 내닉네임` 으로 판단하지 마세요.**
> 두 사람 이름이 같을 수 있습니다(둘 다 "수진"). 그러면 **둘 다 자기
> 차례로 착각합니다.** 서버는 이름이 아니라 **연결**로 구분하기 때문에,
> 프론트엔드도 `your_turn` 을 봐야 서버와 판단이 일치합니다.

`first_turn` 은 **이 게임의 선공**이라 끝까지 안 바뀝니다.
`turn` 은 **지금 차례**라 한 수마다 바뀝니다. 시작할 때만 값이 같습니다.

## 차례가 아닐 때 놓으면

```json
{
  "type": "error",
  "message": "지금은 엘리님 차례입니다",
  "turn": "엘리",
  "your_turn": false
}
```

연결은 끊기지 않습니다. 상대에게도 아무것도 가지 않습니다.

> 📌 **내 차례가 아닐 때는 놓기 버튼을 잠가 두세요.** 어차피 서버가
> 거절하지만, 미리 잠그면 사용자가 헛수고를 하지 않습니다.

시작 전에 놓으면 `아직 게임이 시작되지 않았습니다` 가 돌아옵니다.

# 단어 놓기 · 보드 상태

플레이어가 칩을 놓고 제출하면, 백엔드가 **판과 맞춰 보고 인정되면 실제로
판에 올립니다.** 그러면 **양쪽 모두에게** 판이 갱신됩니다.

## 판은 서버가 기억합니다

두 사람이 함께 보는 판은 **하나뿐**이고, 그 하나가 서버에 있습니다.
각자 화면에만 기억하면 서로 다른 판을 보게 되는데, 그때 어느 쪽이 맞는지
판단할 방법이 없습니다.

> 📌 **`GET /api/game/setup` 의 보드와는 다른 것입니다.**
> 저쪽은 **칸의 성격**(글자 2배 등)이고 절대 안 바뀝니다.
> 이쪽은 **지금 놓인 글자**이고 매 수마다 바뀝니다.
> 화면에서는 두 개를 겹쳐서 그리면 됩니다.

## 보내기 — 단어가 아니라 **좌표**

```javascript
ws.send(JSON.stringify({
  type: "submit",
  tiles: [
    { row: 7, col: 7, letter: "C" },
    { row: 7, col: 8, letter: "A" },
    { row: 7, col: 9, letter: "T" }
  ]
}));
```

| 필드 | 설명 |
|------|------|
| `row` | 위에서부터 몇 번째 줄인지 (**0~14**) |
| `col` | 왼쪽부터 몇 번째 칸인지 (**0~14**) |
| `letter` | 알파벳 한 글자. 소문자도 됨 |

**이번에 새로 놓는 칩만** 보내세요. 이미 판에 있는 글자는 넣지 않습니다.

> 📌 **왜 완성된 단어(`{"word":"CAT"}`)가 아니라 좌표인가**
> 단어만 보내면 판 어디에 놓인 것인지 알 수 없습니다. 점수는 어느 칸에
> 놓였는지에 따라 달라집니다(글자 2배 칸 등).
> **좌표가 원본이고 단어는 거기서 나오는 결과입니다.**

### 빈 타일 놓기

`?` 를 그대로 보내지 말고 **쓸 글자와 함께 `blank: true`** 를 보내세요.

```javascript
{ row: 7, col: 9, letter: "T", blank: true }   // 빈 타일을 T 로 씀
```

**왜 표시가 필요한가:** `letter: "T"` 만 보면 서버는 그게 진짜 T 인지
빈 타일인지 알 수 없습니다. 그런데 **빈 타일은 0점**이라, 모르면 점수가
틀립니다.

| 보낸 것 | 서버가 하는 일 |
|---|---|
| `blank` 없음 | 진짜 글자로 봄. 손에 없으면 그때만 빈 타일을 씀 |
| `blank: true` | **진짜 글자가 손에 있어도** 빈 타일을 씀 |

손에 빈 타일이 없는데 `blank: true` 를 보내면 `손에 빈 타일이 없습니다`.

> 📌 **순서는 상관없습니다.** 좌표만 맞으면 서버가 줄 세워서 읽습니다.

### 놓는 규칙

- **한 줄로** — 가로 또는 세로
- **첫 수는 한가운데(7, 7)를 지나야 함** — 이 규칙이 없으면 구석에서
  시작할 수 있고, 그러면 가운데 점수 칸들이 의미가 없어집니다
- **두 번째부터는 이미 놓인 글자에 닿아야 함** — 따로 떨어져 못 놓습니다
- **이미 글자가 있는 칸에는 못 놓음**
- **사이가 비면 안 됨** — 단 **이미 놓인 글자가 사이를 메우는 건 됩니다**
- **1~7개** — 한 개만 놓아도 됩니다(붙어서 단어가 되면 인정)

### ⚠️ 새로 생기는 단어가 **전부** 사전에 있어야 합니다

가로로 한 단어를 놓아도, 그 글자들이 위아래 글자와 붙으면서 **세로 단어가
여러 개 새로 생깁니다.** 그것들도 전부 진짜 단어여야 합니다.

**하나라도 사전에 없으면 아무것도 놓이지 않습니다.** 일부만 놓으면 판이
반쯤 바뀐 채로 남아 되돌릴 수 없기 때문입니다.

## 받기 ① `word_checked` — 보낸 사람에게만

```json
{
  "type": "word_checked",
  "valid": true,
  "placed": true,
  "direction": "across",
  "words": [
    { "word": "ON", "valid": true, "tiles": [ ... ] },
    { "word": "TO", "valid": true, "tiles": [ ... ] }
  ]
}
```

| 필드 | 설명 |
|------|------|
| `valid` | 새로 생기는 단어가 **전부** 사전에 있으면 `true` |
| `placed` | **판에 실제로 올라갔는가.** `true` 면 바로 뒤에 `board_updated` 가 옵니다 |
| `direction` | `across`(가로) 또는 `down`(세로) |
| `words` | 이번 수로 **새로 생긴 단어 전부.** 하나가 아닐 수 있습니다 |
| `reason` | `valid: false` 일 때만. 어느 단어가 사전에 없는지 |

거절될 때:

```json
{
  "type": "word_checked",
  "valid": false,
  "placed": false,
  "direction": "across",
  "reason": "사전에 없는 단어입니다: XT, CX",
  "words": [
    { "word": "XT", "valid": false, "tiles": [ ... ] },
    { "word": "CX", "valid": false, "tiles": [ ... ] }
  ]
}
```

`words` 안의 `valid` 를 보고 **어느 단어가 문제였는지 화면에 표시**하면 됩니다.

> 📌 **`valid: false` 는 error 가 아닙니다.** 없는 단어를 낸 건 게임에서
> 흔한 일입니다. `error` 는 **애초에 놓을 수 없는 자리**인 경우입니다.

## 받기 ② `board_updated` — **양쪽 모두에게**

```json
{
  "type": "board_updated",
  "by": "수진",
  "direction": "across",
  "tiles": [
    { "row": 7, "col": 6, "letter": "C" },
    { "row": 7, "col": 7, "letter": "A" },
    { "row": 7, "col": 8, "letter": "T" }
  ],
  "words": ["CAT"],
  "board": [ [ "", "", ... ], ... ]
}
```

| 필드 | 설명 |
|------|------|
| `by` | 놓은 사람의 닉네임 |
| `tiles` | 이번에 **새로 놓인** 칩. 방금 자리를 반짝이게 하는 데 쓰세요 |
| `words` | 이번 수로 새로 생긴 단어들 |
| `board` | **판 전체 (15줄 × 15칸).** 빈 칸은 `""` |
| `blank_spots` | **빈 타일로 놓인 자리 전부** `[[row, col], ...]` |

`tiles` 안의 각 칩에도 `blank` 가 붙어 옵니다.

> 📌 **`board` 에는 글자만 들어 있습니다.** 빈 타일을 `S` 로 놓으면 판에는
> `"S"` 라고만 남아서, 그 칸이 빈 타일이었다는 걸 알 수 없습니다.
> **`blank_spots` 로 구분**해서 화면에 다르게 그리세요 — 그 칸은 0점입니다.
>
> 이 값이 없으면 나중에 그 칸을 지나는 단어의 점수가 화면과 서버에서
> 달라집니다.

> 📌 **놓은 사람에게도 옵니다.** 자기 화면을 자기가 그리지 말고 `board` 를
> 받아서 그리세요. **판은 언제나 서버가 준 것이 맞습니다.**

> 📌 **바뀐 부분만이 아니라 판을 통째로 보냅니다.** 프론트엔드가 조각을
> 모아 맞추다 한 번이라도 놓치면 그 뒤로 계속 어긋납니다. 통째로 받으면
> 매번 정확합니다.

`game_started` 에도 `board` 가 들어 있습니다. 시작 시점에는 비어 있지만,
**판은 언제나 서버가 준 것을 그린다**는 규칙을 한 군데도 깨지 않기 위해
그때도 보냅니다.

## 잘못 보냈을 때

| 상황 | `message` |
|------|-----------|
| 첫 수가 한가운데를 안 지남 | `첫 단어는 한가운데(7, 7)를 지나야 합니다` |
| 이미 놓인 글자에서 떨어짐 | `이미 놓인 글자에 붙여서 놓아야 합니다` |
| 이미 글자가 있는 칸 | `이미 글자가 있는 칸입니다 (7, 6): C` |
| 한 줄이 아님 | `한 줄로(가로 또는 세로) 놓아야 합니다` |
| 사이가 빔 | `칩 사이가 비어 있습니다. 붙여서 놓아주세요` |
| 단어가 안 만들어짐 | `단어가 만들어지지 않았습니다 (2글자 이상)` |
| **내 차례가 아님** | `지금은 OO님 차례입니다` (`turn`·`your_turn` 함께 옴) |
| **이미 끝난 게임** | `이미 끝난 게임입니다` |
| 게임 시작 전 | `아직 게임이 시작되지 않았습니다` |
| 상대가 아직 없음 | `아직 상대가 들어오지 않았습니다` |
| 아무것도 안 보냄 | `놓은 칩이 없습니다` |
| **손에 없는 칩** | `손에 없는 칩입니다: Z` |
| **빈 타일이 없는데 `blank: true`** | `손에 빈 타일이 없습니다` |
| 8개 이상 | `한 번에 7개까지만 놓을 수 있습니다` |
| 보드 밖 | `보드 밖입니다. row·col 은 0~14 사이여야 합니다` |
| 같은 칸 두 번 | `같은 칸에 두 번 놓았습니다` |
| `?` 를 그대로 보냄 | `letter 는 알파벳 한 글자여야 합니다. 빈 타일은 쓸 글자를 정해서 보내주세요` |
| 좌표가 숫자가 아님 | `row 와 col 은 정수여야 합니다` |

## 사전

- **20만 4천 단어.** 저장소의 `data/words.txt` 에 들어 있습니다.
- **고유명사는 빠져 있습니다.** (Seoul, Kim 등은 스크래블에서 못 씁니다)
- 2~15자. 대소문자 가리지 않습니다.

> 📌 **왜 백엔드가 판단하는가**
> 프론트엔드에서 판단하면 사용자가 그 코드를 고쳐서 아무 단어나 통과시킬 수
> 있습니다. 브라우저에서 도는 코드는 누구나 열어 보고 바꿀 수 있습니다.
> **점수가 걸린 판단은 반드시 서버에서** 해야 합니다.

## 놓은 뒤 — 손패 보충과 점수

놓기에 성공하면 `word_checked` 에 **손패·가방·점수**가 함께 옵니다.

```json
{
  "type": "word_checked",
  "valid": true,
  "placed": true,
  "words": [ { "word": "CAT", "valid": true, "tiles": [ ... ] } ],

  "rack": ["E", "A", "R", "S", "T", "L", "I"],
  "drawn": ["L", "I"],
  "tiles_left": 84,
  "score": {
    "words": [ { "word": "CAT", "score": 10 } ],
    "words_score": 10,
    "bingo": 0,
    "total": 10
  }
}
```

| 필드 | 설명 |
|------|------|
| `rack` | **놓은 뒤의 내 손패.** 쓴 칩이 빠지고 채워져 다시 7개 |
| `drawn` | 이번에 **새로 뽑은 칩.** 화면에서 새 칩을 표시하는 데 |
| `tiles_left` | 가방에 남은 개수 |
| `score` | **이번 수 점수** (아래 참고) |

`board_updated` 에는 **양쪽 다 알아도 되는 것**이 들어갑니다 —
`score`(이번 점수), `scores`(누적 점수판), `tiles_left`, `partner_tile_count`.
**`rack` 은 안 들어갑니다.** 상대에게 내 칩을 알려주는 셈이 되니까요.

### 손패 규칙

- **손에 있는 칩만 놓을 수 있습니다.** 없으면 `손에 없는 칩입니다: Z`
- 놓은 **개수만큼** 가방에서 다시 뽑습니다 → 늘 7개
- 가방이 바닥나면 **있는 만큼만** 뽑습니다. 7개보다 적어질 수 있고, 그건 정상입니다
- **거절되면 손패도 가방도 그대로**입니다. 다시 내면 됩니다

> 📌 **빈 타일은 `?` 가 아니라 정한 글자로 보내세요.**
> 서버는 진짜 글자를 먼저 쓰고, 없을 때만 빈 타일을 씁니다.
> 진짜 `S` 가 있는데 굳이 빈 타일을 `S` 로 쓰는 사람은 없기 때문입니다.

## 점수 계산

세 가지를 더합니다.

| | |
|---|---|
| ① 글자 점수 | 타일마다 정해진 점수 (E=1, Q=10 …) |
| ② 보너스 칸 | 글자 2배·3배, 단어 2배·3배 |
| ③ 빙고 | 한 번에 **7개를 다 쓰면 +50점** |

**계산 순서**: 글자 배수를 먼저 다 적용한 뒤에 단어 배수를 겁니다.
반대로 하면 글자 2배 칸의 효과가 단어 배수에 곱해지지 않아 점수가 작게 나옵니다.

**보너스 칸은 이번에 새로 놓은 자리에서만** 걸립니다. 이미 놓여 있던 글자가
밟고 있는 칸은 그때 이미 썼습니다. 안 그러면 같은 2배 칸을 지나가는 단어마다
계속 우려먹게 됩니다.

**빈 타일은 0점**입니다. 아무 글자로나 쓸 수 있는 대신 점수를 포기하는 것이
빈 타일의 거래 조건입니다.

**한 번 놓인 빈 타일은 계속 0점입니다.** 나중에 그 칸을 지나는 다른 단어를
셀 때도 0점으로 칩니다. 그래서 서버가 `blank_spots` 로 기억해 둡니다.

**여러 단어가 생기면 각각 점수가 붙습니다.** `score.words` 에 단어별로
들어 있어서 화면에 "CAT 10점 + TO 2점" 처럼 풀어 보여줄 수 있습니다.

### 예시

첫 수로 한가운데를 지나 `CAT` 을 놓으면 — C3 + A1 + T1 = 5, 한가운데는
**단어 2배** 칸이라 **10점**.

`C` 가 **글자 2배** 칸에 놓이면 — C3×2 + A1 + T1 = **8점**.

### 누적 점수판

`board_updated` 의 `scores` 에 두 사람 점수가 함께 옵니다.

```json
{ "scores": { "host": 10, "guest": 0 } }
```

점수판은 **둘 다 보는 것**이라 양쪽에 같은 값이 갑니다.
`game_started` 에도 `{"host": 0, "guest": 0}` 으로 들어 있습니다.

# 턴 넘기기 · 게임 끝내기

## 턴 넘기기 — 낼 칩이 없을 때

```javascript
ws.send(JSON.stringify({ type: "pass" }));
```

**자기 차례에만** 넘길 수 있습니다. 아니면 상대 차례를 마음대로 넘겨버릴
수 있습니다.

양쪽에 `turn_passed` 가 옵니다.

```json
{
  "type": "turn_passed",
  "by": "수진",
  "turn": "엘리",
  "your_turn": false,
  "passes": 1,
  "passes_until_end": 2,
  "scores": { "host": 12, "guest": 8 }
}
```

| 필드 | 설명 |
|------|------|
| `passes` | 연속으로 넘어간 횟수 |
| `passes_until_end` | **몇 번 더 넘기면 끝나는지** |

> ⚠️ **세 번 연속으로 넘어가면 게임이 끝납니다.**
> `passes_until_end` 를 화면에 보여주세요 — "1번 더 넘기면 끝납니다".
> 안 보여주면 게임이 갑자기 끝난 것처럼 느껴집니다.

> 📌 **누가 칩을 놓으면 횟수가 0으로 되돌아갑니다.** 연속이 아니면 세는
> 의미가 없기 때문입니다.

## 칩 교환 — 낼 단어가 없을 때

```javascript
ws.send(JSON.stringify({ type: "exchange", tiles: ["Q", "V", "Z"] }));
```

손패의 칩을 가방의 새 칩과 바꿉니다. **차례를 씁니다.**

**넘기기와 다릅니다.** 넘기기는 다음 차례에도 똑같이 막혀 있지만, 교환은
손패를 바꿔서 상황 자체를 바꿉니다. 대신 한 턴을 버리는 값을 치릅니다.

| | 넘기기 (`pass`) | 교환 (`exchange`) |
|---|---|---|
| 손패 | 그대로 | **새 칩으로 바뀜** |
| 차례 | 넘어감 | 넘어감 |
| 점수 | 없음 | 없음 |
| 넘기기 횟수 | +1 | **+1 (함께 셈)** |

### 규칙

- **자기 차례에만**
- 1~7개
- **손에 있는 칩만.** 빈 타일도 `"?"` 로 적어 바꿀 수 있습니다
- **가방에 7개 미만이면 못 바꿉니다** — 막바지에 서로 교환만 반복하면
  게임이 영영 안 끝나기 때문입니다

> 📌 `tiles` 에는 **내놓을 칩을 손에 있는 그대로** 적습니다.
> `submit` 과 다릅니다 — 저쪽은 "이 글자를 놓겠다"라 빈 타일로 대신할 수
> 있지만, 여기는 "이 칩을 내놓겠다"라 대신할 게 없습니다.

### 받기 ① `exchanged` — 나에게만

```json
{ "type": "exchanged", "count": 3,
  "rack": ["E","A","R","S","T","L","I"],
  "drawn": ["S","T","L"], "tiles_left": 84 }
```

`tiles_left` 는 **바뀌지 않습니다.** 뽑은 만큼 도로 넣기 때문입니다.

### 받기 ② `tiles_exchanged` — 양쪽 모두에게

```json
{ "type": "tiles_exchanged", "by": "수진", "count": 3,
  "turn": "엘리", "your_turn": true,
  "passes": 1, "passes_until_end": 2,
  "tiles_left": 84, "scores": { "host": 12, "guest": 8 } }
```

> 📌 **몇 개를 바꿨는지만 갑니다.** 무엇을 내놓고 무엇을 받았는지는
> 알려주지 않습니다. 그걸 알면 상대 손패를 좁혀 나갈 수 있습니다.

> ⚠️ **넘기기 횟수에 함께 셉니다.** 칩을 안 냈으니 넘긴 것과 같습니다.
> 교환·넘기기를 합쳐 **3번 연속이면 게임이 끝납니다.**
> 누가 실제로 칩을 놓으면 0으로 돌아갑니다.

### 잘못 보냈을 때

| 상황 | `message` |
|------|-----------|
| 차례가 아님 | `지금은 OO님 차례입니다` |
| 가방이 부족함 | `가방에 칩이 7개 미만이면 바꿀 수 없습니다 (남은 N개)` |
| 손에 없는 칩 | `손에 없는 칩입니다: Z` |
| 아무것도 안 고름 | `바꿀 칩을 골라주세요` |
| 두 글자 이상 적음 | `칩은 한 글자씩 적어주세요` |
| 8개 이상 | `한 번에 7개까지만 바꿀 수 있습니다` |
| 이미 끝난 게임 | `이미 끝난 게임입니다` |

## 나가기 (기권)

```javascript
ws.send(JSON.stringify({ type: "resign" }));
```

**점수와 상관없이 남은 사람이 이깁니다.** 그만둔 사람을 이기게 하면
지고 있을 때 나가버리는 게 이득이 되어 버립니다.

> 🔴 **되돌릴 수 없습니다.** 보낸 순간 진 것이 됩니다.
> 버튼을 누르면 "정말 나가시겠습니까?"로 한 번 되묻고 보내세요.

> 📌 **연결은 끊기지 않습니다.** 결과를 보고 다시 시작할 수 있어야 하기
> 때문입니다. **탭을 닫는 것과는 다릅니다** — 탭을 닫으면 지금까지처럼
> `guest_left`/`host_left` 가 가고 방이 정리됩니다.

## 게임이 끝나면 — `game_over`

**양쪽 모두에게** 갑니다. 끝나는 길이 세 가지이고 `reason` 으로 구분합니다.

| `reason` | 언제 |
|---|---|
| **`finished`** | 가방이 비고 누군가 손패를 다 씀 |
| **`passed`** | **세 번 연속으로 칩을 안 냄** (넘기기·교환 합쳐서) |
| **`resigned`** | 한 사람이 나가기를 누름 |

> 📌 **승패는 쌓아온 점수만으로 가립니다.** 손에 남은 칩은 점수에
> 반영하지 않습니다. 점수판에 보이던 숫자가 마지막에 갑자기 달라지지
> 않아서, 보고 있던 대로 결과가 납니다.
> (`resigned` 만 예외 — 점수와 상관없이 남은 사람이 이깁니다)

```json
{
  "type": "game_over",
  "reason": "finished",
  "winner": "수진",
  "you_won": true,
  "scores": { "host": 84, "guest": 61 },
  "board": [ ... ],
  "at": "2026-08-15T15:20:03.114000"
}
```

| 필드 | 설명 |
|------|------|
| `winner` | 이긴 사람 닉네임. **비겼으면 `null`** (화면 표시용) |
| **`you_won`** | **받는 사람 본인이 이겼는가.** 비겼으면 `null` |
| `scores` | **최종 점수.** 쌓아온 점수 그대로 (가감 없음) |
| `by` | **`resigned` 일 때만.** 나간 사람 |
| `board` | 끝난 시점의 판 |
| `at` | DB가 찍은 종료 시각 |

> 🔴 **`winner === 내닉네임` 으로 판단하지 마세요.** 이름이 같으면 둘 다
> 이긴 것으로 착각합니다. **`you_won`** 을 보세요. (차례의 `your_turn` 과 같은 이유)

### 승패 판정

**쌓아온 점수를 그대로 비교합니다.** 손에 남은 칩은 보지 않습니다.

원래 스크래블에는 "남은 칩만큼 점수를 깎는" 정산 규칙이 있지만, 이
프로젝트에서는 **빼기로 정했습니다.** 그래야 게임 내내 보고 있던 점수판이
그대로 결과가 되고, 마지막에 순위가 갑자기 뒤집히지 않습니다.

`resigned` 만 예외입니다 — **점수와 상관없이 남은 사람이 이깁니다.**

### 끝난 뒤

- `submit`·`pass` → `이미 끝난 게임입니다`
- `resign` → `지금은 나갈 게임이 없습니다`
- **방장이 `{"type":"start"}` 를 다시 보내면 새 게임이 시작됩니다.**
  판·손패·점수가 모두 비워집니다.

### 기록

DB `rooms` 에 남습니다 — `ended_at`, `end_kind`, `winner`,
`host_score`, `guest_score`. `started_at` 과 짝이라, 둘이 있으면
"언제 시작해서 언제 어떻게 끝났는가"가 한 판의 기록이 됩니다.

## ⚠️ 아직 없는 것

| 없는 것 | 그래서 지금 |
|---------|-------------|
| 지난 판 다시 보기 | 결과만 DB에 남고 오간 수는 안 남습니다 |
| 무르기 | 놓은 수를 되돌리는 것. 없습니다 |


# 아직 없는 것 (중요)

한 판이 처음부터 끝까지 돌아갑니다. 아래는 아직 없는 것들입니다.

- **재접속** ← 가장 큰 구멍입니다. 게임 화면에서 **새로고침하면 그 판이
  통째로 사라집니다.** 방·손패·판이 전부 서버 메모리에만 있어서, 연결이
  끊기면 되돌아올 방법이 없습니다
- **차례에 시간 제한이 없습니다.** 상대가 자리를 비우면 그 판은 멈춥니다.
  기다리는 쪽이 쓸 수 있는 건 **나가기 버튼**뿐입니다
- 랜덤 매칭(`matched`)으로 만난 사람은 **자기가 방장인지 알 수 없습니다.**
  `matched`에 그 정보가 없어서, 시작 버튼을 눌러보기 전에는 모릅니다
- **2~4인 게임** — `rooms.max_players`는 2~4명인데 코드는 **2명만** 다룹니다
- 지난 판 다시 보기 — 결과만 DB에 남고 **오간 수(기보)** 는 안 남습니다
- 상대가 읽었는지 표시 (읽음 확인) · 상대가 입력 중인지 표시
- 방장과 친구가 **같은 닉네임**이어도 막지 않습니다
  (그래서 `your_turn`·`you_won` 같은 값이 따로 있습니다)

> 위 항목들은 각각 별도 기능 단위로 진행합니다.

> ⚠️ **방은 서버 메모리에만 있습니다.** DB에는 "이런 방이 있었다"는 기록만
> 남고, 실제 연결은 켜져 있는 서버에만 존재합니다. 그래서 **서버를 껐다 켜면
> 살아 있던 방은 전부 무효**가 됩니다. 개발 중에는 자주 일어납니다.
