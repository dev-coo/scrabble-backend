# 웹소켓 명세서 (스크래블) — 백엔드

> 최종 수정: 2026-08-08
> 현재 범위: **연결 확인용 통로 하나.** 실제 기능은 아직 없습니다.

## 이 문서가 왜 따로 있나

HTTP API는 FastAPI가 스와거(`/docs`)와 `/openapi.json`을 **자동으로** 만들어 줍니다.
하지만 **웹소켓은 자동 문서화가 안 됩니다.** `/docs`에 들어가도 `/ws`는 보이지 않습니다.

그래서 이 문서가 **웹소켓의 계약서**입니다. 이게 없으면 프론트엔드는
"뭘 보내고 뭘 받는지" 알 방법이 아예 없습니다.

- `docs/api-contract.md` — 스와거가 대신 만들어 주는 것을 옮겨 적은 문서
- `docs/ws-contract.md` (이 문서) — **대체제가 없어 반드시 손으로 써야 하는 문서**

> 프론트엔드 저장소에도 **같은 내용의 `docs/ws-contract.md`**가 있어야 합니다.
> 바꿀 때는 양쪽을 함께 고치고, 멘토(은우)가 일치를 확인합니다.

## 웹소켓은 HTTP와 뭐가 다른가

| | HTTP API | 웹소켓 |
|---|---|---|
| 방식 | 물어보면 답하고 **끊음** | 한 번 연결하면 **계속 이어져 있음** |
| 누가 먼저 말하나 | 프론트엔드만 | **양쪽 다** |
| 언제 쓰나 | 목록 조회, 저장 등 | "누가 방에 들어왔다"처럼 **남 때문에 생긴 일**을 알릴 때 |

프론트엔드가 물어보지 않아도 백엔드가 먼저 말을 걸 수 있다 — 이게 핵심 차이입니다.

## ① 접속 주소

```
ws://localhost:11000/ws
```

`http://`가 아니라 **`ws://`** 입니다. 포트는 HTTP API와 **같은 11000**을 씁니다.
(같은 서버가 두 가지를 함께 처리합니다.)

## ② 접속할 때 넘기는 값

**없습니다.** 그냥 연결하면 됩니다.

> 방 번호·닉네임 같은 값은 아직 받지 않습니다. **누가 어느 방에 연결했는지
> 서버는 지금 구분하지 못합니다.** 그건 방 입장 기능을 붙일 때 정합니다.

## ③ 접속 직후 서버가 먼저 보내는 것

연결되자마자 서버가 **먼저** 이 메시지를 보냅니다.

```json
{ "type": "connected", "message": "웹소켓 연결됨" }
```

> 프론트엔드는 이걸 받아야 "연결 완료"를 확신할 수 있습니다.
> 연결 상태 표시등(●)을 켜는 시점으로 쓰세요.

## ④ 프론트엔드 → 백엔드 (보내는 메시지)

**아무 문자열**이나 보내면 됩니다. 형식이 정해져 있지 않습니다.

```javascript
ws.send("안녕");
```

> 지금은 연결 확인용이라 형식이 없습니다. 실제 기능이 붙으면
> `{"type": "...", ...}` 형태의 JSON으로 바뀝니다.

## ⑤ 백엔드 → 프론트엔드 (받는 메시지)

**항상 JSON**이며, **`type` 필드로 종류를 구분**합니다.
앞으로 종류가 늘어나도 `type`만 보고 갈라내면 되도록 정한 규칙입니다.

| `type` | 언제 오나 | 형태 |
|--------|-----------|------|
| `connected` | 연결 직후 1회 | `{"type":"connected","message":"웹소켓 연결됨"}` |
| `echo` | 내가 뭔가 보냈을 때 | `{"type":"echo","message":"<내가 보낸 문자열 그대로>"}` |

```javascript
ws.onmessage = (e) => {
  const data = JSON.parse(e.data);   // 문자열로 오므로 JSON.parse 필요
  if (data.type === "connected") { /* 연결됨 표시 */ }
  if (data.type === "echo")      { /* 되돌아온 내용 */ }
};
```

> **`echo`는 임시입니다.** 보낸 말을 그대로 되돌려 주는 것뿐이라,
> "선이 진짜 양방향으로 통하는지" 눈으로 확인하는 용도입니다.
> 실제 기능이 붙으면 사라집니다.

## ⑥ 연결이 끊기는 경우

| 상황 | 무슨 일이 생기나 |
|------|------------------|
| 브라우저 탭·창을 닫음 | 정상 종료. 서버는 에러로 보지 않습니다. |
| 서버를 껐다 켬 (`--reload` 포함) | **연결이 끊깁니다.** 자동으로 다시 연결되지 않습니다. |
| 네트워크가 끊김 | 연결이 끊깁니다. |

> ⚠️ **끊기면 프론트엔드가 직접 다시 연결해야 합니다.**
> 서버는 끊긴 상대를 기억하지 않고, 먼저 다시 걸지도 않습니다.
> `ws.onclose`에서 재연결을 시도하도록 만드는 건 프론트엔드 쪽 몫입니다.
>
> 개발 중에는 백엔드가 코드를 고칠 때마다 서버가 다시 시작되므로
> **연결이 자주 끊깁니다.** 정상입니다.

## 아직 없는 것 (중요)

지금은 **통로만** 있습니다. 아래는 **하나도 구현돼 있지 않습니다.**

- 여러 사람에게 동시에 알리기 (한 명이 보낸 걸 다른 사람들이 받는 것)
- 방 구분 (누가 어느 방에 있는지)
- 누가 연결했는지 식별 (닉네임·플레이어 id)
- 연결이 끊긴 사람 정리

> 지금 두 명이 각각 접속해도 **서로의 메시지는 보이지 않습니다.**
> 각자 자기 메아리만 받습니다. 위 항목들은 각각 별도 기능 단위로 진행합니다.

## 확인 방법

브라우저 개발자도구 콘솔에서 바로 해볼 수 있습니다.

```javascript
const ws = new WebSocket("ws://localhost:11000/ws");
ws.onmessage = (e) => console.log("받음:", e.data);
ws.onclose = () => console.log("끊김");
// 연결된 뒤에
ws.send("안녕");
```

기대 결과:

```
받음: {"type":"connected","message":"웹소켓 연결됨"}
받음: {"type":"echo","message":"안녕"}
```
