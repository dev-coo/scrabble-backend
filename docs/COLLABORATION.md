# 협업 가이드 (사람용)

> 최종 수정: 2026-07-29

이 문서는 **팀원(사람)이 읽는 진행 안내서**입니다.
Claude의 코드 작업 규칙은 각 저장소의 `CLAUDE.md`에 따로 있습니다.

> 프론트엔드·백엔드 저장소에 **같은 내용**이 들어 있습니다. 고칠 때는 양쪽 다 고칩니다.

---

## 1. 역할

| 사람 | 계정 | 역할 |
|------|------|------|
| **수진** | `sujin` | 프론트 / 백 개발 (로테이션) |
| **엘리** | `ellie` | 프론트 / 백 개발 (로테이션, 수진과 반대편) |
| **은우** | `eunwoo` | 총괄 · 멘토 (진행 관리, 리뷰, API 계약 조율, DB 운영) |

세 계정 모두 **같은 컴퓨터**에 있습니다. 그래서 서로 `localhost`로 접속합니다.

## 2. 로테이션

한 사람이 프론트·백을 번갈아 맡아 **양쪽 티어를 모두 경험**하는 것이 목표입니다.

| 페이지 | 프론트 | 백엔드 |
|--------|--------|--------|
| 대기실 | 수진 | 엘리 |
| 플레이 | 엘리 | 수진 |

- **은우**는 로테이션·리뷰·API 계약 합의를 총괄하고, 데이터베이스를 띄워 둡니다.

## 3. 포트 (고정)

| 구분 | 포트 | 담당 |
|------|------|------|
| 프론트엔드 | 10000 | 수진 |
| 백엔드 | 11000 | 엘리 |
| 데이터베이스 | 5432 | 은우 (Docker) |

이 세 포트는 스크래블 전용으로 예약합니다.

## 4. "기능 단위"란

한 번의 요청 = 기능 하나. 페이지 전체는 기능 단위가 **아닙니다.**

- ✅ 좋은 단위: "방 목록 UI", "방 생성 API(`POST /rooms`)", "닉네임 입력 필드"
- ❌ 너무 넓음: "대기실 페이지 만들어줘", "백엔드 다 만들어줘"

넓게 요청하면 Claude가 거절합니다. 스스로 쪼개 오거나, 정 모르겠으면 Claude에게 **"추천해줘"**라고 하세요.

> 못 해서 막는 게 아닙니다. **쪼개서 이름 붙이는 연습**이 이 프로젝트의 목적입니다.
> 그 기록이 `PROMPTS.md`에 남고, 그게 회고 자료가 됩니다.

## 5. 프론트 ↔ 백 API 계약 합의 절차

프론트와 백은 **API라는 약속(계약)**으로만 연결됩니다. 코드보다 계약을 먼저 맞춥니다.

1. 기능을 시작하기 전에 **프론트·백 담당이 API 계약을 함께 정합니다.**
   - 엔드포인트 (예: `POST /players`)
   - 요청 형식 (보내는 JSON)
   - 응답 형식 (받는 JSON)
   - 에러 형식
2. 각 저장소의 `docs/api-contract.md`에 **같은 내용**을 기록합니다.
3. **은우가 양쪽 계약이 일치하는지 확인**합니다.
4. 합의 후 각자 독립적으로 개발합니다.
   - 프론트는 백이 늦으면 **목(mock) 데이터**로 먼저 진행할 수 있습니다.

백엔드가 API를 만들면 **스와거 문서(`http://localhost:11000/docs`)** 가 자동으로
갱신됩니다. 프론트 담당은 이걸 보고 호출을 맞추면 됩니다.

## 6. 티어 경계

| 티어 | 하는 일 | 하지 않는 일 |
|------|---------|--------------|
| 프론트엔드 | 화면, 사용자 입력, **API 호출** | DB 직접 접근 ❌ |
| 백엔드 | 비즈니스 로직, API 제공, **DB 접근** | 화면 그리기 ❌ |

**프론트엔드는 데이터베이스에 직접 붙지 않습니다.** 반드시 백엔드 API를 거칩니다.
그래서 DB 접속 정보는 백엔드 저장소에만 있습니다.

## 7. 커밋 규칙

- **기능 하나 완성 = 커밋 하나** (약간 널널해도 됨).
- 커밋 메시지는 무엇을 했는지 알 수 있게. (예: `feat: 방 목록 UI 추가`)
- 지금 단계에서는 **`main`에 바로 푸시**합니다. (PR 절차는 나중에 도입)
- **작업 시작 전에 항상 `git pull` 로 최신화**하세요.

## 8. 프롬프트 기록

- Claude에게 입력한 프롬프트는 `PROMPTS.md`에 자동 기록됩니다.
- 주기적으로 커밋/푸시해서 **서로 어떤 지시를 했는지 비교·회고**합니다.
